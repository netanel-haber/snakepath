# Agent Guidelines for snakepath

C99 STB-style header-only pathlib port. No malloc, POSIX + Windows. All code in `snakepath.h`.

Record every wish, rule or learning the maintainer states in this file (in the same change), not only in private notes.

## Code Philosophy
- All logic in `snakepath.h`; no logic in `snakepath.py` or the C harness (the `SP_PYTHON` extension module in `test.c`), which stay one-to-one glue. Code outside it is glue or Python-specific only (argument coercion, exception classes and messages, Python protocols like `NotImplemented`, harness stubs); path semantics always go in C first.
- Minimize API surface, share `sp_priv_*` internals
- No one uses the library yet, so backward compatibility is not a constraint: judge API and behavior changes on their merits (correctness, simplicity, CPython fidelity)
- No special-casing in wrappers
- Fluent API has near-parity with boring API — only iterators missing; a fluent method returns what the function it forwards to returns
- One C function stands for a family of pathlib methods when the API still reads well, differing from Python's names as long as its comment lists them: `sp_is(p, type, follow_symlinks)` is exists and the ten `is_*` predicates, `sp_stat(p, follow_symlinks)` is stat and lstat, `sp_copy(.into)`/`sp_move(into)` are the `_into` variants, `sp_rename(replace)`, `sp_link_to` (symlink_to, hardlink_to), `sp_remove` (unlink, rmdir, and `_delete` with `.recursive`), `sp_info(p, info, type, follow_symlinks)` (`Path.info`'s exists, is_dir, is_file, is_symlink), `sp_match(.full)` (match, full_match), `sp_glob_begin(.recursive)` (glob, rglob). Merges favor families of three or more; `with_name`/`with_stem`/`with_suffix` and the six components stay separate because `sp_stem(&p).buf` reads better than a tagged call, and owner/group stay separate by the maintainer's earlier decision.
- Full parity with pathlib 3.15 (the maintainer, 2026-11-01: "We need full parity with pythons pathlib 3.15"): every pathlib feature works through the bindings. What has a C meaning is in C (`Path.info`, `_delete`); Python-only machinery is glue in `snakepath.py` (pickling through `__reduce__`, `_parse_path`, `PurePath.as_uri`'s `DeprecationWarning`, pathlib's docstrings and `pathlib.types`, copied from the host's pathlib), and the harness stands in for pathlib's module layout (`pathlib._local`). Only tests that mock a Python function inside CPython's own implementation stay expected failures, because passing them would hand the logic to Python (`is_junction` through `os.path.isjunction`, `copy`'s `fcntl.ioctl` fast path).
- Parity work is test-driven (the maintainer: "do the parity using tdd"): the C test, the `check_fs` comparison or the CPython test taken out of `EXPECTED_FAILURES` comes first and is shown failing, then the code that makes it pass.
- Macros are for constants, names for hacks (C/C++ compat casts, platform functions, compiler attributes like `SP_NODISCARD`) and the simplest iterator sugar (`SP_*_FOREACH`). Never use a macro to share code.
- Two X-macro lists are the exceptions the maintainer accepted, because one list keeps parallel tables from drifting: the fluent method tables, and `SP_ERRORS(X)`, which defines `SpError`, `sp_error_str`'s messages and the harness's error constants from one row per code. Nothing else in the public API is generated.

## Errors
Shift every error as far left as it goes: what can be a compile error is one, what can be an explicit runtime error is one.
- One `SpError` for everything, path logic and OS alike, with specific codes (`sp_priv_last_error` maps errno and `GetLastError`). A result that can fail carries it (`.error` on paths, text, suffixes, stat results and iterators); actions return it.
- A path with an error passes it on: every function returning a path, text or struct returns the input's error, and actions return it, so a chain needs one check at the end. Functions returning a bool or a number, and `sp_str`, assert that their paths carry no error. An error path is empty.
- Every public function that returns a value is `SP_NODISCARD`; bad configuration macros are `#error`s.
- A function returning an `SpPath` returns one named result on every path after that variable is declared (an error is made in it in place with `sp_priv_set_error(&r, err)`: assigning `sp_priv_error_path`'s result copies all 4 KB, which doubled `sp_resolve`'s instructions when `sp_readlink` did it per part), or a call before it is, so the compiler builds the result in the caller's variable instead of copying 4 KB out (the maintainer: "Can't we support nrvo?"). clang's `-Wnrvo`, part of `-Weverything` since clang 21, fails the build on a `return name;` that misses this; a `return cond ? a : b;` copies silently, so write those as an assignment and `return r;` too. gcc never elides a result whose address is taken (passed to `readlink`, `sp_priv_normalize`), so where an error return is the hot path, read into the result in a block of its own and return the error after the block, as `sp_readlink` does: clang still elides (every return inside the block is the result) and gcc's error return builds a fresh empty path without a copy.
- Nothing is silently truncated or skipped: a result that doesn't fit its buffer (`SP_PATH_MAX` or the caller's) is `SP_ERR_TOO_LONG`, going past a configured limit (`SP_MAX_SUFFIXES`, `SP_GLOB_MAX_DEPTH`, `SP_GLOB_PATTERN_MAX`) is `SP_ERR_LIMIT`.
- Options: a function with one option takes a named bool; one with two or more takes a struct of them (`SpCopyOptions`, `SpMkdirOptions`, `SpWalkOptions`, `SpLinkOptions`, `SpRemoveOptions`, `SpMatchOptions`, `SpGlobOptions`), fields named after pathlib's keywords, so a wrong option is a compile error rather than a runtime `SP_ERR_INVALID_ARG` (the maintainer: "comptime beats all"). Zero-initialized options are pathlib's defaults unless the field says otherwise (`bottom_up`, not `top_down`, so that zero is os.walk's default; `follow_symlinks` on copy is the documented exception). Callers write `(SpCopyOptions){.into = true}` in C; before C++20 they set the fields of a zero-initialized variable, which is what `test.c`'s `*_opts` constructors do because the tests build as C++ too. The header itself never uses compound literals. Modes are always explicit (0 is a mode; `SP_MODE_DIR`/`SP_MODE_FILE` are pathlib's defaults).
- A fluent chain started while another runs carries `SP_ERR_NESTED_CHAIN` (both chains do, until the next terminator).

## Call Depth and Stack
`snakepath.py` measures two things on the preprocessed library (`cc -E -P`, or `cl /EP` on Windows, with `SNAKEPATH_IMPLEMENTATION` and `SNAKEPATH_FLUENT`) and bounds both with hardcoded limits (`FRAME_LIMIT`, `STACK_BUDGETS`):
- **Frames**: every function the library defines is a frame (public, `sp_priv_*` and `static inline` alike, plus qsort comparators); a function calling itself is exempt. At most 6 snakepath frames from a public function down; a fluent method is one more on top, so 7. Indirection has a price of its own, which is why this bound stays even though it is not the stack risk.
- **Stack bytes**: each function's own frame from `-fstack-usage` at `-O0` (gcc or clang; skipped with a message where neither exists), summed along the heaviest call chain below every public function, at `SP_PATH_MAX` 4096 and 1024. Budgets: 128 KB and 64 KB, 1/16 of Windows' 1 MB default stack at its `SP_PATH_MAX`. Frames depend on the compiler (clang for the MSVC ABI at `-O0` measures about 4× gcc's), so the budgets hold for the worst measuring environment and the printed chains are the numbers to compare. This is the real constraint the frame count used to stand in for.
- The check prints leads, not just a verdict: the functions at the frame limit, the heaviest chain per configuration and the heaviest frames. Read them before a compression pass; a frame-forced duplicate or a large stack buffer shows up there first.
- Never pass either check by hiding a call behind a private wrapper or a macro. Prefer entry → helper → leaf, leaves taking what they need precomputed. With 6 frames a public function may call another public function and still have room (`sp_resolve` → `sp_absolute` → `sp_priv_join_len` → `sp_priv_normalize` → `sp_priv_split_anchor` → `sp_priv_drive_len` is the limit).
- History: the limit was 3, then 4 (PR #88), then 6 with the stack budget (2026-09-27), when the maintainer judged that the frame count alone had been forcing duplicates (`copy_into`, `move_into`, the cwd sites, the Windows readlink step) that a byte bound doesn't.
- `SpPath` carries its `anchor` and `drive` lengths, set by `sp_priv_normalize` (every constructor ends there) and kept by truncation (`sp_priv_prefix`); `SP_ASSERT_PATH_INVARIANT` recomputes and checks them. Code reads the fields instead of calling `sp_priv_split_anchor`, which is for raw text (a glob pattern).
- A path's flavor is never `SP_FLAVOR_NATIVE`: making a path resolves it, so code tests `flavor == SP_FLAVOR_WINDOWS` and `c == '/' || c == sep` inline instead of calling predicate helpers.

## Code Layout
Code should breathe, balancing readability and brevity:
- Divide functions into paragraphs (setup, guards, main loop, cleanup, result) with blank lines where they separate ideas. Whitespace should mean something: no ceremonial blank lines or braces (no C#-style layout).
- One statement per line. `if`/`for`/`while` bodies never share the condition's line: no `if (x) return y;`, `while (...) i++;` or `for (...) {}`. A single-statement body goes on the next line without mandatory braces.
- No statement compression to save lines: no comma-chained declarations of unrelated variables, no packed ternary chains where plain statements read better.
- The layout is enforced with clang-format 21. The style lives in `nob.h` (`SNAKEPATH_LAYOUT`, passed as `--style=`), because tool configuration goes on nob's command lines rather than into extra repo files. `./nob format` applies it, and the default `./nob` run fails if `snakepath.h`, `trim.h` or `logo.c` isn't formatted: the C this repo writes is held to `snakepath.h`'s readability standard (the maintainer, 2026-11-07). CI pins clang-format with `pip install clang-format==21.1.8`, so every environment formats identically.
- **Net LOC is always reported post format.** Run `./nob format` first, then measure. A line delta taken before formatting, or earned by packing statements or deleting blank lines, is not a result.

## Refactoring Rules
Good: extract helpers, delegate to primitives, early return, remove dead code.
Bad: shorten names, define convenience macros, remove whitespace/braces, add macro layers that only reduce LOC before preprocessing.
Rule: semantic compression must compress the expanded code too. If `cc -E -P` turns the "cleanup" back into the same amount of code, more code, or harder-to-follow code, it is not a cleanup.

## Pseudo Commands

### `/sem-compress [path] [optional goal]`

The `sem-compress` skill, with snakepath's rules:
- Scope: `snakepath.h` only unless the maintainer names other files. Touch `snakepath.py`, `test.c` or other files only where a header change forces it, and list other ideas in the report instead of doing them.
- Read `README.md` and `snakepath.h` in full before editing. The expanded form a refactor is judged by is `cc -E -P` of the touched region.
- Keep public API sections concrete. Prefer small implementation-local helpers over public macro inventories, and stop at changes that add slot-order coupling.
- "Never make the library even slightly worse" includes more stack or frames (the checks below) and C-runtime side effects (examples under Learnings).
- Ship a change only if it alone is net −60 lines or more (post format). When the maintainer asks for the small things, bundle real simplifications (each a removed layer or dead branch, never cosmetic) into one PR, and say plainly that no single item clears −60.
- When a change rewrites pure path logic (parsing, normalizing, joining, matching), prove it behaves identically with `./nob diff` (default base `origin/main`). It builds `test.c` as the `SP_DIFF` driver against both headers, which prints every public result per input over exhaustive short strings over `/\ac:.?U`, token sequences (`\\?\UNC\` and `\\.\` prefixes, drives, case-folding pairs, which random generation never hits) and random strings, in both flavors and at `SP_PATH_MAX` 64 and 16. nob splits each set into 16 parts, runs one driver per core, compares the outputs while the drivers write them and prints each set's first difference as soon as both sides have it (the input and the labeled results that differ), then how many lines differ; the base side's drivers and outputs are cached in `diff_base/` while the base header, `test.c` and the build commands stay the same, so a repeat run only builds and runs the working tree's side. CI runs the same check against the PR's base on Linux and Windows (`diff-linux`, `diff-windows`), the only differential coverage of Windows-only pure logic such as `collapse_dots`: read its report. An intentional behavior change differs by design, so the job is informational and never blocks a merge. The check must stay fast enough to run locally whenever it helps: the maintainer asked for about 30 seconds on their phone and accepted the speed of 2026-09-27 (a repeat run about 10 s with Termux in the foreground, where it gets all 8 cores, and about 40 s in the background, where Android gives it 3), and it reports the first differences as soon as it finds them, so a broken change is fixed while the rest still runs. When it gets slower, profile the driver and make the library (or the driver's glue) faster rather than running it less.
- Format with `./nob format`, then verify with `nob`. Baseline a possibly environmental failure against clean `main` with `./nob clean`.
- The report adds the `./nob diff` result, locally and from CI's `diff-windows` job, to the skill's.

## Testing

Snakepath is developed from any environment: Linux, macOS, Windows, Android and so on. CI (Linux and Windows) is authoritative.

```bash
cc -x c -o nob nob.h && ./nob   # everything: builds, C/C++/fluent tests, Python checks, layout check, demo
./nob format                    # rewrite snakepath.h in its clang-format layout
./nob python                    # only the Python bindings, their checks and CPython's pathlib tests
./nob clean                     # remove build artifacts (use before baseline comparisons)
./nob diff [ref]                # the pure path API against the header at a git ref (default origin/main), old vs new
./nob snake                     # snake.c, the site's export: logo.c with the snakepath it uses, cut down by trim.h
```

MSVC builds nob with `cl /Tcnob.h`, and `-DSNAKEPATH_QUIET` quiets nob's command echo. Requirements are a C compiler, CPython 3.15 or later (the bindings refuse to import on older ones), and clang-format 21. Environment knobs:
- `SNAKEPATH_SKIP_GCC=1`: clang builds only (where `gcc` is missing or is really clang).
- `SNAKEPATH_SANITIZE=1`: add sanitizer builds.
- `VERBOSE=0`: fewer logs.

**Direct commands for focused debugging:**

```bash
gcc -std=c99 -I. -Wall -Wextra -Werror -o test_snakepath test.c && ./test_snakepath
g++ -std=c++11 -x c++ -I. -Wall -Wextra -Werror -Wmissing-field-initializers -o test_cpp test.c && ./test_cpp
python snakepath.py --build && python snakepath.py   # the bindings' extension module for this Python, then the checks
```

**g++ pitfalls:** `{0}` → `memset`, `void*` casts → `SP_PRIV_CAST`, C casts → `SP_PRIV_CAST`, pointer to integer → `SP_PRIV_PTR_BITS`. A struct's first member must not be an enum (clang warns that `{0}` converts an int to it).

**`SP_NODISCARD` pitfall:** GCC's `warn_unused_result` ignores `(void)` casts, so store or check every result (the tests assert them, cleanup included).

**Environment quirks:** Android forbids hard links, and CPython there has no `os.link`: `sp_hardlink_to` returns `SP_ERR_UNSUPPORTED` on Android (`pathlib.UnsupportedOperation`), and the tests expect that.

## EXPECTED_FAILURES

Dict in `snakepath.py` mapping error substrings → `(class_name, test_name)` tuples. Runner verifies failure reasons, reports wrong-reason and unexpected-success. It holds only the tests that mock Python functions inside CPython's implementation (see Code Philosophy); a test failing for any other reason is a gap to close, not an entry.

## Known Issues

- Windows CI: race condition with parallel MSVC builds
- The test binaries' `main` holds hundreds of paths in one frame, past Windows' 1 MB default stack at `/Od`: nob links them with `/STACK:8388608`
- clang 21 added `-Wnrvo` to `-Weverything` (the Linux runner moved to Ubuntu 26.04 and its clang 21 around 2026-10-27): CI failed on `main` at 13 copied returns, which the `SNAKEPATH_NO_NRVO` knob only silenced. - The call-depth check measures the host's preprocessed header, so a Windows-only call chain (like `sp_is`'s mount-point test through the case tables) shows only in `build-windows`. To see it from Linux, run `check_frames` with `CC` set to a wrapper around `zig cc -target x86_64-windows-gnu`

## Learnings

- The bindings are a CPython C-API extension module, `_snakepath` (`test.c` with `-DSP_PYTHON`), built against the stable ABI (`Py_LIMITED_API` 3.15, `abi3`): one build runs on every CPython from 3.15 on, at no measured cost against a version-specific build. `python snakepath.py --build` makes `_snakepath.abi3.so` (`.pyd` on Windows) next to `snakepath.py` with that Python's headers (nob runs it; cl.exe on Windows), and `snakepath.py` loads whichever `_snakepath` sits beside it. They were ctypes, whose 400-500 ns per call and 4 KB `SpPath` per Python path made `Path(str)` 3.4 us against pathlib's 0.4 and every everyday operation slower than pathlib's. The maintainer (2026-11-02): "There are no users. Just make the bindings nothing", "Dont micro optimize bindings - if the issue is the overarching mechanism (ctypes) - switch that". A path is an `SpPath` object holding just its text, anchor, drive, flavor and error, its `str` and hash made once, rebuilt as a C `SpPath` on the stack for each call; iterdir and glob come back whole in one call (pathlib's iterdir lists before it yields too), walk is an iterator object because its caller prunes between steps. The costs of a C-API module: crashes instead of exceptions for refcount mistakes, the stable ABI's narrower API (heap types from specs, no fast-path macros or private functions), and no `abi3` for free-threaded CPython yet. libffi doesn't sidestep it: ctypes is libffi, and its cost is converting Python objects for each call, which only code written against Python's own API avoids.
- `pip install snakepath` takes a wheel (the maintainer, 2026-11-02, asking how "an unassuming lib" would get the right build; "Do the best thing"): `pyproject.toml` packages `snakepath.py` and the extension (setuptools, its `ext-modules` table, tagged `cp315-abi3`), the one support file the rule against them gives way to, since pip can't install without it. CI's `wheels` job builds them with cibuildwheel (Linux x86-64 and ARM, manylinux and musllinux; macOS Intel and ARM; Windows x64 and ARM64), tries each where its runner can run it, and fails on a symbol outside the stable ABI (abi3audit); `sdist` builds the source package for every other platform, which compiles on install. Nothing is uploaded to PyPI (the maintainer, 2026-11-02: "We arent uploading to pypi at all, ever, yet"): the wheels and the sdist are CI artifacts only, and the workflow has no publish job or tag trigger. Add one only when the maintainer asks. `import snakepath` loads only what the classes need (the build and the checks import `subprocess`, `sysconfig`, `unittest` and `urllib` where they use them): it cost 85 ms more than `import pathlib`, which black paid on every run.
- The bindings support CPython 3.15 and later only, and parity holds with every 3.15 release (the maintainer, 2026-11-02, asked whether pathlib's tests must pass per Python version: "Option 1 for now. Parity with all sub version of python3.15"). Older pathlibs differ from 3.15's (3.13 has no `copy`, and the fuzz finds thousands of differences on 3.13 and 3.12), so supporting them would mean a library with one behavior per version. CI's `parity` job runs `python snakepath.py` (fuzz, `check_fs` and CPython's pathlib tests) on Linux and Windows for each 3.15.x that `actions/setup-python` lists, read from its versions manifest so a new release joins by itself; the tests come from the running CPython's release tag (`v3.15.2`), cached as `cpython_tests/test_pathlib_v3_15_2.py`. On 2026-11-02, 3.15.0, 3.15.1 and 3.15.2 passed all three, and their `test_pathlib.py` files were identical.
- black is the proof that switching a pathlib-heavy program to snakepath pays (the maintainer, 2026-11-02: "find a python library that does a hell of a lot of path ops using pathlib that can become 10% faster just by switching to snakepath, build it and prove it"). `black --check` on a formatted, cached tree is all discovery and cache checks, a third of it `relative_to` (13 us a call in CPython 3.15's pathlib, about 1 us in C); black 26.10.1, pure Python, on 8 copies of CPython 3.15's standard library (5,544 files, a `.gitignore` per copy), its five `from pathlib import Path` lines made `from snakepath import Path`, `-v` output identical line for line: median of 9 to 15 alternating runs 1,084 ms with pathlib, 530 ms with snakepath (2.05x); the ctypes bindings managed 1.10x. Per operation on 3,000 real paths against pathlib: `relative_to` 16x, `parent`, `with_suffix`, `resolve`, `iterdir`, `rglob` 2-3x, the existence checks 1.4x; constructing a path (0.4x), `str`, joins, the components, eq/hash and `stat` (a namedtuple) are still slower, the Python-level glue around one fast call. The benchmark and the corpus are scratch, like the others.
- Keep wrapper layers thin: one-to-one calls only, no logic that replaces core behavior.
- Prefer `nob` as the canonical local test entrypoint; use the raw compile commands only when narrowing a specific failure.
- For cleanup work, optimize for semantic compression, not line-count compression. The real measure is the concrete C the compiler sees, not the source LOC count.
- Semantic compression must survive preprocessing. A refactor only counts if the `cc -E -P` output is also smaller, flatter, or clearer in substance.
- If a macro refactor only hides repetition in the source file but expands back to the same wrapper boilerplate, it is not simplification; it is indirection.
- Use the preprocessed view (`cc -E -P`) to judge macro refactors. Keep a macro only if the expanded code is still obviously simpler than the handwritten alternative.
- Public API sections should stay concrete. If repetition remains, prefer tiny implementation-local helper macros over public X-macro inventories.
- Removing blank lines and packing statements is not compression; it made the library hard to read, and the layout check now rejects it.
- Before treating a local filesystem/fluent failure as a regression, stash the patch, run `./nob clean`, verify clean `main`, then compare against that baseline.
- Python bindings should use `os.fspath()` directly (no `str()` fallback) so non-pathlike types raise `TypeError`.
- Text crosses into the extension as UTF-8 with lone surrogates passed through (WTF-8) and its length, so embedded NULs and the bindings' surrogates survive; a path is an immutable `_snakepath.SpPath` that `_from_sp` shares rather than copies.
- `owner`/`group` return `SP_ERR_UNSUPPORTED` on Windows (the bindings raise `pathlib.UnsupportedOperation`), so their wrappers are built everywhere.
- Windows goes through the wide (W) API only: `sp_priv_native` turns a path into what the OS takes (UTF-16 from WTF-8 in a `SP_PRIV_NATIVE_MAX` buffer on Windows, the path's own bytes on POSIX), and `sp_priv_from_wide` brings text back. Files are read and written through native handles (`sp_priv_open`/`read`/`write`/`close`), never the C runtime, so error codes come straight from the OS.
- A function that talks to the OS (`sp_stat`, `sp_readlink`, `sp_mkdir`, `sp_cwd`, and the private `open`, `remove_impl`, `link_to_impl`) takes `const SpPath *` and converts it itself into an `SpPrivNative` (`.path` is what the OS takes, `.buf` its UTF-16 storage on Windows), so callers carry no conversion prologue. Where a public function is the whole implementation (`sp_stat`, `sp_readlink`, `sp_mkdir`, `sp_cwd`, `sp_join_n`), internal code calls it directly instead of a private twin: a public function may call another public function within the frame budget.
- Caching the anchor and drive in `SpPath` was a wash at 4 frames (every constructor needed its own split line) and pays once `sp_priv_normalize` computes them, which needs the 6-frame limit.
- `sp_stat(p, follow_symlinks)` is both `stat` and `lstat`, like `exists`/`is_dir`/`is_file`; `len(p.parts)` and `len(p.parents)` are counted by the caller through the iterators (the harness and bindings do), not by the library.
- `SpStatResult.sp_reparse_tag` is CPython's `st_reparse_tag` (lstat's tag on Windows, 0 elsewhere): `sp_is_junction` and the recursive delete test it instead of opening the file again.
- Scanning a path for the next separator goes through `sp_priv_part_end` (a leaf, so it fits under any caller); a new inline `while (... != '/' && ... != sep)` loop is a duplicate.
- Windows link behavior follows CPython: `lstat` reports `S_IFLNK` only for symlinks, `symlink_to` makes a directory link to an existing directory, `unlink` removes directory links, `readlink` returns the substitute name, `resolve` is `ntpath.realpath`, and files are copied with `CopyFile2`.
- `walk` is an iterator (`sp_walk_begin`/`sp_walk_next`/`sp_walk_end`) keeping names in the caller's buffer, in `os.walk`'s shape: the bindings drive it as a generator and hand pruned `dirnames` back between yields, with no walk logic in Python.
- `sp_with_segments` now takes a `parts_count` (no NULL-terminated arrays); use `SP_ARRAY_LEN`.
- New functionality goes in `snakepath.h` first; then mirror module functions in the `SP_PYTHON` section of `test.c` and in `snakepath.py`, plus tests in `test.c` (fluent API tests under `#ifdef SNAKEPATH_FLUENT`). The bindings keep pathlib's method names and map them onto the merged C functions (`is_dir` is `sp_is(SP_DIR, follow)`, `rglob` is `sp_glob_begin` with `recursive`); a module function takes Python values and builds the option struct, which is glue.
- `SP_GLOB_FOREACH(base, pattern, options, var)` takes an `SpGlobOptions` value (`(SpGlobOptions){0}` in C); there is no separate rglob macro.

- The 2026-11-01 hill-climb (gcc / clang, best-of-9 totals 1774 / 1842 ms -> 468 / 431 ms):

  - a `*` followed by an ASCII literal passes over ASCII that can't start the rest without a recursive call;
  - a relative `match` pattern scans back from the end over only as many parts as the pattern has, instead of walking every part twice;
  - `sp_priv_prefix`, `sp_priv_join_len` and `sp_relative_to` copy only the text, not the whole `SpPath`;
  - a recursive glob's last wildcard is matched in the walk's own listing: CPython lists each directory twice for `**/*.py` without `recurse_symlinks`, and its matches are the same set (pathlib defines no order). A part with more after it stays its own selector, since it may name a link the walk doesn't enter;
  - files copy with `sendfile` on Linux, falling back to read and write when it can't take the file.
- Safety from CVEs is paramount, as is parity with CPython 3.15 (the maintainer, 2026-11-02: "Parity with cpython3.15 is paramount. Safety from cves is paramount"), and what other projects do is taken where it fits ("Everything that makes sense for an iterator based no malloc lib"). Lessons taken from bfs, Rust's std, CPython, GNU coreutils, Go's WalkDir, ripgrep's walkers and Git for Windows' fscache:
  - The recursive delete (`sp_priv_rmtree`, one function for both platforms, listing through `sp_priv_readdir_next`) is safe from links swapped in while it runs (CVE-2022-21658), as Rust's `remove_dir_all` makes it: on POSIX every directory opens through the one it is in with `O_NOFOLLOW | O_DIRECTORY` and what is in it is removed relative to it (`unlinkat`); on Windows, where CPython's rmtree isn't safe, each directory is held open, without sharing delete access, from the check on its handle that it is no link or junction to its removal through that handle (`FileDispositionInfo`). What vanished below the top is skipped, as CPython skips it. Like CPython's `_rmtree_safe_fd`, a directory is entered only when its `fstat` matches the `lstat` taken through its parent before it opened (which catches a real directory moved in mid-delete). Dropping that check to save lines was undone: what CPython checks, snakepath checks (the maintainer, 2026-11-02: "If cpython makes a check readd it"), even when asked to win back lines ("if its possible to get a net 0, lets do so"). The path-based delete deleted a file outside the tree in 5 of 6 runs of `test.c`'s race test (a forked process swapping a subdirectory for a link out), which the safe delete can never fail. With no memory for CPython's full listing, a directory left not empty after a pass that removed something is read once more (a file system may miss entries removed while it is read).
  - glibc's strict C modes hide POSIX 2008's open flags and `*at` functions: there the header defines the flags from glibc's internal `__O_*` names and `AT_FDCWD`, `AT_REMOVEDIR` and `AT_SYMLINK_NOFOLLOW` as Linux's values (so strict builds' `chmod(follow_symlinks=False)` takes `fchmodat` too, like every other build), and declares the functions as it declares `lstat`. `utimensat`'s branch keys off `UTIME_OMIT`, which those modes hide too.
  - Every file opens with `O_CLOEXEC` (PEP 446: CPython's files aren't inherited), and files copy as CPython copies them: FICLONE, then `copy_file_range` where glibc declares it (`_GNU_SOURCE`), then `sendfile`, each falling through on CPython's errors; a first 0 from `copy_file_range` falls through too (older kernels copied nothing of procfs files), and a file `sendfile` refuses is read and written.
  - Walk, glob frames and copy list a directory through the handle of the one it is in (`SpPrivDirAt`, `openat` + `fdopendir`), with `O_NOFOLLOW` where the step doesn't follow links: two more syscalls per directory (`fdopendir`'s `fcntl`s) and still faster than `opendir` on the whole path (about 10% on drizzle's tree, 30% on a deep one), and a link swapped in can't send the step elsewhere. `test.c` races a walk the way it races the delete: the path-based walk listed the outside directory in 3 of 4 runs.
  - The walk keeps each level's listing open until the level is done, so it has an end function like the other iterators (`sp_walk_end`, which the bindings call in their generator's `finally`). A name the caller adds to `dirnames` is walked into following links, as `os.walk` walks into it, so each level keeps a sorted copy of what its listing found (`listed`) to tell the two apart. On Windows a level closes its listing at once: a held handle keeps a subdirectory deleted bottom-up pending, so its parent not empty.
  - Not taken, as it doesn't fit an iterator library that allocates nothing: reading directories with `getdents64` into a buffer of snakepath's own (bfs's 64 KiB), parallel walks (bfs, `ignore`, fastwalk), and a cache of what was listed (Git for Windows' fscache), which would be state across calls.
- The file system workloads sit at their syscall floor: `opendir` costs `openat`, `fstat`, two `getdents64` and `close` per directory (glibc's, with no portable way around it), `resolve` makes glibc's one `readlink` per part, and recursive delete matches `rm -r` (no stat per entry; the safe delete adds CPython's `lstat`, `fstat` and `fdopendir` per directory). Off limits: `sp_path_cmp` comparing whole strings with the separator sorting first (plus a `low` byte its other callers pass as `'\0'`); one fluent table whose chainable methods clear and re-set the active flag; an owner/group helper switched by a flag; glob relying on the normalizer keeping a `.` before a drive-like part; reuse that adds a stack buffer or a frame (`readlink` and `path_convert` through a temporary buffer, `resolve` through `absolute`); Windows mkdir/unlink/rmdir through the C runtime, whose error codes rely on `GetLastError()` surviving the call; a macro that drops an argument.
